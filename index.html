What is Dash Platform?

Core handles DASH payments. Platform adds identities, human-readable usernames and shared documents: the building blocks of a contact list, a post or a poll. Data contracts define which documents an app can store.

Shared data for apps, secured by Dash

Evonodes agree on updates. Your app can check a proof that an answer matches the network’s signed data, instead of trusting the server that delivered it. That checks what was stored, not whether its content is true.

One app action, three steps

Imagine saving a contact called Maya in an app. An identity is the account doing the saving; a data contract defines the shape of a contact.

  1. 1. Write

    Your app signs an update with your identity’s key and pays a small credit fee. The contact must follow the app’s contract.

  2. 2. Agree

    Evonodes check the signature and rules, agree on the update, and store it. Other apps can read the same permitted data.

  3. 3. Read and check

    An app asks for the contact and checks a proof against the network’s signed state. It can verify that “Maya” is what was stored, even if the answering server is unfamiliar.

Public data stays public: use app-specific privacy controls for anything sensitive. A proof confirms stored data; it cannot tell you whether Maya’s details are true.

For builders: from app to network

Your app uses an SDK to sign updates and ask an evonode for data. The evonode runs the rules and stores the result; your device checks the answer using a proof. You can use the SDK without implementing these layers yourself.

The map below names the software behind those three steps. Drive and GroveDB provide both the server’s query code and the client’s proof checks. A root hash identifies the stored state; a quorum’s BLS threshold signature attests to it. Select a component for the implementation details and source.
